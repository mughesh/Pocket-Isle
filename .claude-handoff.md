## Setting up a new PC
1. Install **Git LFS** before cloning (fonts, PNGs and DLLs are LFS): `git lfs install`
2. Clone: `git clone https://github.com/mughesh/Pocket-Isle.git`
3. Unity **6000.3.25f1** (6.3 LTS) with Android Build Support (SDK/NDK, OpenJDK).
4. Open the project, then **File > Build Profiles > Meta Quest** (switch if it isn't active).
5. Open `Assets/_Project/Scenes/MR_Main.unity` (the game). `Diorama.unity` is the Step 1 art scene, Editor only.

## Testing in Editor Play over Link
- **Meta Horizon Link app > Settings > Beta:** Developer Runtime Features, Passthrough over Meta Quest Link,
  and Spatial Data over Meta Quest Link all on. Link app version should match the SDK (v207+).
- **Project Settings > XR Plug-in Management > Windows tab > Initialize XR on Startup** (committed as **on**):
  - On: headset must already be in the Link home **before** pressing Play, or the Editor freezes
    (Meta's runtime waits for a headset; nothing in our code causes it).
  - Off: flat Play, no freeze. Arrow keys = swipes, Space = tap, R = re-place island.
- Mugesh doesn't want an editor menu toggle for this. He flips the checkbox himself.

## Gotchas already learned
- The **Interactions Rig building block ships with locomotion** (gravity character controller, thumb-swipe
  teleport/turn). It falls forever in MR and eats our swipes. If the rig is ever reinstalled, run
  **Tools > Diorama > Step 2 > 3. Disable Rig Locomotion**.
- Microgesture events fire **once per swipe**. There's no "held" state from the API; that's what the probe tests.
- ISDK v207 uses the **OpenXR joint set** (`ISDK_OPENXR_HAND` is always defined): `HandIndex0` = metacarpal,
  `HandIndex1` = proximal, etc. Confirm joint names in the package source, not old docs.
- `Assets/XR/APILayers~/` holds Meta's agentic OpenXR API layer (`XrApiLayer_METAX_operator`, Windows only),
  enabled in OpenXR settings for the Windows target. Committed so clones match.
